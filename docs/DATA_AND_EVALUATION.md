# 数据与评估协议

## 1. 本地文件

真实数据不随仓库发布。将样本置于 `NGC6517/` 或配置指定位置，清单默认放在 `splits1/`。

CSV 必须有 `packed_path` 与一个标签字段，优先使用 `label_bin`、其次 `label_int`、最后 `label`。推荐统一填写整数 0/1。兼容明确的 `rfi/noise/false/no` 和 `pulsar/psr/true/yes` 等标签；未知值报错，不自动归为 RFI。

相对 `packed_path` 依次相对 CSV 上一级目录、CSV 所在目录解析；清单中的反斜杠会转为斜杠。推荐例子：CSV 放在 `splits1/train.csv`，样本路径写 `NGC6517/sample.npz`。不要依赖其他机器的绝对盘符。

可选元数据包括 `sample_id`、`sigma`、`red_chi2`、`best_dm`、`p_topo_s`、`dm_nu2_score`，具体变换以加载器为准。

NPZ 必须支持 `profile`、`dm_curve`、`subints`、`subbands` 字段。旧文件可能含对象数组，加载器使用 `allow_pickle=True`，因此仅使用可信本地数据。

## 2. 清单检查

训练/搜索前检查：

1. CSV 存在且非空，列和标签合法；
2. 所有样本文件存在，无重复路径；
3. 每个类至少有 `k_shot + q_shot` 个样本，避免通过重复抽样构造 episode；
4. train/val 的文件路径和非空 sample_id 没有交集；
5. 最终评估时再将 test 清单加入交集检查。

路径与 sample_id 无交集不等于没有科学泄漏。同一源、同一观测时段或同一物体的多个候选可能高度相关，需要按来源分组划分。此版不会自动读取文件内容推断物理来源，也不按 NPZ 内容哈希去重。

## 3. Episodic 训练

每个 episode 从 RFI 和 Pulsar 两类中，各抽取 `k_shot` 个支持样本与 `q_shot` 个查询样本。支持集和查询集在 episode 内不重叠。编码器学习共享嵌入，查询对支持集原型做分类。

默认 `k_shot=q_shot=20`、`episodes=500`。episode 是小样本任务次数，不是遍历所有样本的 epoch，二者不能直接等同。

训练采用 AdamW、交叉熵及梯度范数裁剪。数据清单、超参数和种子应作为实验协议一并冻结。

## 4. 验证与检查点选择

每 `eval_every` 次训练进行验证。验证使用两组可重复抽样的 episode bank：种子分别为 `eval_seed` 和 `eval_seed+2`。为兼容旧参数名称，第二组仍叫 `VAL_RANDOM`，但本版本在各检查点之间复用其抽样，以减少比较噪声。

`eval_seed` 默认是训练 seed+10000。默认选择分数为 `0.7 × F1(bank1) + 0.3 × F1(bank2)`，它是两个 bank 的 F1 加权平均，不是把混淆矩阵相加后计算的全局 F1。

选择验证 F1 最高的检查点，F1 接近时用更低的误分类成本打破平局。启用 `auto_threshold` 时仅在验证集选阈值，同样先比较 F1、再比较成本。成本由 `cost_fn` 与 `cost_fp` 加权。

连续用验证集搜索仍可能过拟合验证集，因此需要限制搜索预算，并在最终方案冻结后评估独立测试集。0.90 等目标仅是停止条件。

## 5. 独立最终测试

训练与自动搜索默认不加载测试样本，也不产生逐检查点测试预测。使用：

```bash
python agent.py evaluate JOB_ID
```

使用成功任务中的最佳检查点及其源码快照、参数、验证阈值，在测试划分运行独立的固定 episode bank（默认种子 eval_seed+1）。评估过程不更新梯度，不重新训练，不搜索测试阈值。

该协议在测试划分内部提供每类带标注支持样本，再对不重叠查询集评分。它衡量的是测试划分上的 few-shot 分类能力，不能等同于零样本、开放集或无标注支持集的在线部署能力。

重复 episode 可能复用测试样本，因此 episode 预测条数不是独立样本数；本版没有估计置信区间。正式结论应补充分组划分、多种子结果和合适的统计分析。

## 6. 输出与历史结果

- `summary.json`：最佳验证结果、阈值、所选权重及可选最终测试结果。
- `history.json`：训练损失和验证轨迹。
- `test_predictions.csv`：只在显式最终测试时生成。
- `manifest.json` / `trial_manifest.json`：代码、参数、清单摘要、运行命令和 Python 信息。

原目录中的旧结果保持不变，但不会自动混入新任务排名。因为旧版曾以 test_f1 反馈搜索，旧结果不能直接解释为本版严格独立测试协议下的结果。
